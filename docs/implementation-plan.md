# Mini Redis 实现与验收计划

状态更新时间：开始实现前。完成测试后在文末「状态」一节改写，不删原先的设计约定。

本文件是正式桌面程序的实现计划。仓库根目录最初只有一行标题的 `README.md`。随附的 HTML / 原型 README 只作为交互和文案参考，不作为后端，也不作为正确性标准，不把模拟页面当成可运行的正式程序。

## 目标

做一个 Windows x64 的绿色便携桌面程序：解压目录后直接运行，不需要安装程序，也不要求用户另装 .NET、WebView2 或浏览器壳。配置和操作记录只放在可执行文件所在目录。界面固定为连接 / 键列表 / 键详情三栏，中文。

## 技术选择（已对照当前工具链）

依据微软支持策略页（页面标注 Last updated: November 10, 2026）：

- .NET 10：2025-11-11 首发，LTS，支持阶段 Active，支持结束日 2028-11-14。
- .NET 11：2026-11-10 首发，STS，不是本程序的目标框架。
- .NET 8 与 .NET 9 在该页「Out of support」表中，结束日 2026-11-10。

本仓库在实现时用官方 `dotnet-install` 的 `10.0` 通道安装到的 SDK 为 **10.0.404**。`global.json` 把 SDK 固定在 10.0 功能带并允许补丁前滚，不使用预览包，也不把目标框架写成 `net11.0`。

Windows 桌面范围以 Microsoft Learn「Install .NET on Windows」当前表格为准（.NET 10 列）：

- Windows 11（26H1、25H2、24H2、23H2 Ent/Edu）x64
- Windows 10（21H2、1809、1607；该页说明 Windows 10 仅限 LTSC 与 Enterprise）x64
- Windows Server 与 Server Core（2025、23H2、2022、2019、2016、2012 R2、2012）x64，以及列出的 Nano Server x64

只发布 **win-x64**。桌面目标框架是 `net10.0-windows10.0.17763.0`（Windows 10 版本 1809 的 API 集）。上面的表还列出 Windows 10 1607 LTSC/Enterprise，本程序没有把目标平台降到 1607，所以不把 1607 写成最低版本。不发布 x86 / Arm64，也不把 Windows 7 / 8.1 写成支持平台。该页写明 Windows Server 2012 / 2012 R2 仍可能需要 Visual C++ 2015–2019 可再发行组件，因此不把这些老系统说成「完全零依赖」。

发布形态：

- `dotnet publish -c Release -r win-x64 --self-contained true`
- `PublishSingleFile=false`
- `IncludeNativeLibrariesForSelfExtract=false`
- 产物是目录，再打成 ZIP
- 不使用单文件自解压 exe，避免运行时把本机库解到 TEMP
- ZIP 内应能直接看到 `MiniRedis.exe` 以及 `coreclr.dll`、`hostfxr.dll` 等运行时文件

Redis 传输使用 NuGet 上的 **StackExchange.Redis 3.4.35**（稳定版，兼容 net10.0）。不自写 RESP。选择理由：二进制值有 `byte[]` 转换，TLS / ACL / 超时由该库维护；它的 `ExecuteAsync` 一次发送一条命令。高层次的 `Keys()` / `CursorEnumerable` 会在内部连续 SCAN，业务代码禁止使用。该库的 `ExecuteAsync` 没有 `CancellationToken` 参数，取消发生在两条命令之间，并在单条命令尚未返回时停止等待；下一条命令会等这一条在连接上结束，避免游标状态交错。不为此另写协议栈。

这个库把 `KEYS` 当成管理命令。连接设置 `AllowAdmin=true`，否则用户确认后的 `KEYS` 也不会离开本机。这不是安全开关。`FLUSHDB`、`FLUSHALL`、`SHUTDOWN` 仍在调用 `Execute` 之前拒绝。

界面是 WinForms 标准控件。没有内嵌网页，没有 WebView2，没有本地数据库。

## 路径与便携

根目录一律是 `AppContext.BaseDirectory`（可执行文件目录），不用进程当前工作目录。

- 连接配置：`{根}/data/connections.json`
- 操作记录：`{根}/logs/audit.jsonl`，轮转文件仍在 `logs/`
- 启动时在这两个目录做一次写入探测

目录不存在则创建。没有写权限时抛出明确错误，说明完整路径，并写明不会改存到 AppData 或其他位置。禁止静默回退。配置写入采用同目录临时文件再替换，避免半截 JSON。日志追加失败时保留已有完整行，把失败告诉界面，不把 Redis 已执行的结果改写成成功或失败。

便携目录可以整个搬走。密码不承诺可移植（见下节）。

## 连接与秘密

连接项包含名称、主机、端口、逻辑库、ACL 用户名（可空）、TLS、是否接受不受信任证书（默认否）、连接超时、命令超时。

密码默认只留在本次进程内存，退出即丢，不写入配置。可选「保存密码」时，仅在 Windows 上用 DPAPI `DataProtectionScope.CurrentUser` 加密后，把密文 Base64 放进配置。没有名为 `password` 的明文字段。

DPAPI 范围说明（界面和 README 都要写）：

- 只用当前用户范围，不用 LocalMachine
- 换 Windows 用户或换机器后无法解密
- 不承诺把保存的密码随文件夹拷走还能用
- 非 Windows 或 DPAPI 失败时拒绝保存，不改成明文落盘

日志、命令回显、上下箭头历史、错误对话框都不写密码。连接异常如果带有 `password=` 一类片段，先去掉再显示。

测试不使用用户自己的 Redis，只用临时启动、只绑定 127.0.0.1 的实例，测试结束即结束进程并删除数据目录。测试不调用 `FLUSHDB` / `FLUSHALL` / `SHUTDOWN`。

## 键列表：SCAN

默认模式是 SCAN。连接成功后不自动扫描。

`开始查询` 发出**一条** `SCAN cursor MATCH pattern COUNT hint`，游标从 `"0"` 开始。用户若选择了类型，则在同一条命令上追加 `TYPE`，类型过滤不会再偷偷循环 SCAN，也不会先扫一页再在客户端按类型补扫。服务器不支持 `TYPE` 时显示错误并停止。`COUNT` 只作为提示传给服务器，不把它当成返回条数。

`加载更多` 在已开始且游标未结束时可用，每次点击只再发**一条** SCAN。空批且游标不是 0 不是结束。只有游标按无符号整数解析为 0 才算结束。游标以 Redis 返回的十进制文本原样保存和回传，用 `ulong` 判断是否为 0，不用有符号 32/64 位整数，避免大于 `long.MaxValue` 的游标被解释错。

同一会话里按键的原始字节去重。不在客户端先枚举全部键再分页。

切换连接、逻辑库、模式、类型或 COUNT，以及重新开始查询，都会取消进行中的操作并增加代次。过期代次的结果不得写入新的列表。

`加载全部` 单独确认一次。确认文案写明当前连接、库、MATCH、类型、COUNT，并说明这是连续 SCAN 直到游标为 0，不是 KEYS。模式里若有 `*`，风险说明并进同一次确认，循环内部不再弹窗。可停止。停止或取消后保留已加载键和当前游标，以便继续 `加载更多`。进度只显示已完成的批次数和本批/累计键数，不显示虚构的总数。

界面保护上限（默认最多保留 20000 个已去重键，或最多 10000 批，先到为准）：达到上限就停止，状态必须写明尚未扫完，不能显示成已全部加载。游标保留。

Redis SCAN 不是快照，帮助里说明同一轮里键可能重复或漏掉刚变化的键。

## 精确查询

同一个输入框：

- 整段输入当作完整键名时，只发 `EXISTS`、`TYPE`、`PTTL`（值在选中键之后才读）。不 SCAN，也不在已加载列表里查找。键名里的 `*`、`?`、`[]` 保持字面值。
- 输入以命令形式 `KEYS` 加一个模式时，走另一次 `KEYS`。`KEYS` 即使模式里没有 `*` 也要确认。确认文案说明它是单次阻塞命令，返回全部匹配，不能靠界面分页减轻服务器成本。
- 含 `*` 的字面键名也会先确认，但文案必须说明这次仍是字面查找，不是 KEYS。
- 取消确认不发命令，不记为成功。

`KEYS` 的结果如果超过界面上限，明确说明服务器已经返回全部匹配、界面没有全部放下，不提供伪装成 SCAN 的「加载更多」。

## 键值

选中键之后才读取值。

- String：先 `STRLEN`。不超过 256 KiB 才 `GET`；超过则 `GETRANGE` 预览，标记截断，禁止保存，避免用截断内容覆盖未见过的字节。
- 非 UTF-8：只读十六进制预览，不放进可编辑文本框，保存按钮不可用。
- Hash / Set / ZSet：`HSCAN` / `SSCAN` / `ZSCAN` 按游标翻页，每页一条命令。基数用 `HLEN` / `SCARD` / `ZCARD`，并说明与扫描不是同一快照。
- List：`LRANGE` 按下标翻页，`LLEN` 只作基数。
- 编辑只提交已加载且用户改过的成员（`HSET` / `HDEL` / `SADD` / `SREM` / `ZADD` / `ZREM` / `LSET` / `RPUSH`）。不用当前页替换整个集合。List 不提供按下标删除（避免用临时值和 `LREM` 误伤），需要删除时走命令面板并确认。
- 不支持的类型只显示 `TYPE` 和 `PTTL`，不整块拉取。
- TTL 用 `PTTL` 的毫秒语义：`-1` 无过期，`-2` 键不存在。设置过期用 `PEXPIRE`，清除用 `PERSIST`。不把 `0` 当成「永不过期」（Redis 里会删除键）。
- 删除键是单键 `DEL`，需确认，与清库分开。

## 命令面板

这是 Redis 命令面板，不是操作系统 shell。通用转发，不用产品白名单限制可输入命令。参数解析支持空白分隔、双引号转义（`\\`、`\"`、`\n`、`\r`、`\t`、`\xHH`）和单引号字面量。未闭合引号不发送。

硬拒绝（大小写、首尾空白、引号都算）：命令名是 `FLUSHDB`、`FLUSHALL`、`SHUTDOWN`。确认框不能放行，参数里的 `*` 也不能放行。不发送，不记为成功。

另外拒绝会占用连接、不再是一问一答的命令：`SUBSCRIBE`、`PSUBSCRIBE`、`SSUBSCRIBE`、`MONITOR`、`SYNC`、`PSYNC`。这是传输能力限制，不是安全白名单。

`DEL` / `UNLINK` 在可写模式下确认后可以执行。`KEYS` 始终确认。参数中含 `*` 时确认。多种原因合并成一次确认。

只读模式（默认，且不写入配置，每次启动都是只读）：

- 先取 `COMMAND INFO`。
- 仅当标志里有 `readonly` 且没有 `write` 时允许发送。
- 未知命令、元数据为空、`COMMAND` 失败：拒绝，不发送。
- 因此 `EVAL` / `FCALL` / `MULTI` 这类没有 `readonly` 标志的命令在只读模式下会被拒绝。
- `EVAL_RO` / `FCALL_RO` 若服务器标了 `readonly`，则放行。脚本内写操作靠服务器拒绝。客户端不解析脚本，不能证明模块或旧服务器的标志一定真实。

可写模式：

- 除硬拒绝和连接占用类命令外，未知命令也转发，由服务器和 ACL 决定。
- 不把「首词黑名单」说成能挡住间接危险。`EVAL` / `EVALSHA` / `FCALL` 的脚本、`MULTI`/`EXEC`、模块命令都可能间接执行 `FLUSHALL` 等。客户端做不到可靠拦截。
- 需要限制时，应在 Redis ACL 去掉相应用户的 `flushall`、`flushdb`、`shutdown`、`@dangerous`、`@admin`，以及不需要的 `@scripting`。
- 命令面板每一行是独立请求。多路复用客户端不保证 `MULTI`/`EXEC` 与心跳命令隔离，事务不可靠，也不能当成安全边界。

回显有长度上限。超限时注明已截断，截断本身不是命令失败。

上下箭头历史只保留参数可完整显示的命令。凭据、脚本、未知命令和带写入值的命令不进入历史，避免红acted 文本被再次执行，也避免秘密留在历史里。清屏只清输出，不清操作记录。

## 脱敏

命令回显、历史、操作记录、错误对话框使用同一套规则：

- `AUTH`、`HELLO`、`ACL`、`MIGRATE`、`CONFIG`：只留命令名，参数改为 `[参数已隐藏]`。服务器错误整段改为「执行失败（详情已隐藏）」，因为错误文本可能回显口令或用户名。
- `EVAL`、`EVALSHA`、`EVAL_RO`、`EVALSHA_RO`、`FCALL`、`FCALL_RO`、`SCRIPT`、`FUNCTION`：同样整段隐藏参数和服务器错误。
- 未知命令或没有元数据的命令：有参数就隐藏参数；服务器错误整段隐藏。
- 已知写入命令（如 `SET`、`HSET`、`LPUSH`、`SADD`、`ZADD`）：保留键名，值改为 `[值已隐藏]`。服务器错误里若包含这些值，先替换；值短于 3 个字符时无法安全替换，整段错误改为「执行失败（详情已隐藏）」。
- 任何文本中的 `password=` 片段都要去掉。
- 操作记录不保存返回数据。

取消、硬拒绝、只读拒绝、未真正发出的命令不得记成 `ok: true`。这些情况不写操作记录。真正发出的命令无论成功失败都记一条。

## 操作记录

JSONL，一行一个 JSON 对象，字段只有：上海时区显示时间、`Asia/Shanghai`、UTC 时间、连接名、库编号、脱敏后的命令、成败、失败时的脱敏错误。

显示时间固定为上海（`Asia/Shanghai`，没有则用 Windows 的 `China Standard Time`，再没有则用固定 UTC+8 并在文档说明）。

单文件超过 1 MiB 则轮转，最多保留 5 个文件。界面按时间倒序分批查看。损坏行跳过并提示，不拖垮其他记录。重启后仍能读到。清空需要确认。

界面操作和命令面板共用一个写入器，同一次 Redis 命令只记一条。

## 界面

- 默认窗口约 1280×800，最小约 960×640。
- 三栏放在最小宽度 1160 的区域内。窗口更窄时横向滚动，栏不改成上下堆叠，不按比例把字缩到不可读。
- 颜色克制：浅灰底、白面板、深绿色主按钮。默认只读用单独的颜色，当前连接和库号一直可见。
- 按钮和输入框有简短悬停提示。不散落问号图标，不用长条说明横幅。
- 右上角一个「使用说明」，打开后是普通窗体里的说明文字，讲 SCAN、KEYS、只读边界和 ACL，不讲「这是模拟数据」。

## 测试与 CI

单元测试（不连接用户 Redis）：

- 一次「加载更多」只调用一次 SCAN；空批且游标非 0 不算结束；去重；取消保留游标和已加载键；代次变化后丢弃迟到结果
- `TYPE` 只出现在同一次 SCAN 参数里
- 字面键与 `KEYS`、字面 `*` 的确认文案区分
- 硬拒绝不能被确认绕过；只读模式按元数据放行/拒绝/无法分类时失败关闭；可写模式不拒绝未知命令
- 脱敏覆盖凭据、脚本、未知参数、写入值，以及含这些值的服务器错误
- JSONL 写入、读取、轮转、坏行；取消和拒绝不会记成成功
- 配置路径跟程序根目录走，不跟当前工作目录走；不可写目录报错且不提回退到 AppData 的行为
- 配置文件不含明文密码；保护器不可用时拒绝保存

集成测试：临时 `redis-server`，只绑定回环地址。用 `MONITOR` 确认一次业务 SCAN 在线上只有一条 SCAN。覆盖二进制 GET 不损坏、键名中的 `*` 按字面 `EXISTS` 命中，以及 `COMMAND INFO` 对 `GET` / `SET` / `EVAL` / 不存在命令的分类。集成测试不执行 `FLUSHDB`、`FLUSHALL`、`SHUTDOWN`。
